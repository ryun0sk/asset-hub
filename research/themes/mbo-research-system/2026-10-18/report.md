# 追加のサービス利用料0円で始めるMBOリサーチシステム

設計日：2026-10-18（日本時間）。設計主担当：GPT-6 Astra。ユーザーの「無料で作りたい」という指定に基づく再設計。[当初案](initial-paid-plan.md)と[技術設計](technical-design.md)は比較用に残す。本書は設計全体で、同日にCSV持込・価値計算・週次履歴・専用ローカル画面の初版を実装した。[実際の起動方法と実装範囲](../../../../docs/mbo-weekly.md)を参照。PDF/XBRLの自動抽出、EDINETの自動取得、実企業の初回調査は未実施。銘柄推奨や予測精度の実績ではない。

**既存Mac上で、公開資料と手動入力から候補を探し、上位候補にだけ株価を付けて割安さを調べる。データ契約、クラウド計算、外部LLM・OCRへの支払いを必須にしない。** 基礎版はAPIキーなし・外部接続なしでも、持込資料から全機能が動く設計とする。初期は20〜30社の詳細調査から始めるが、毎回同じ会社だけを見る仕組みにはせず、企業一覧と新しい提出資料から調査対象を追加する。

## 1 無料の範囲と、当初案から変えること

| 項目 | 無料版の方針 |
|---|---|
| 実行環境 | 既存Mac、既存回線、ローカルPython・SQLite・ファイル保存。追加クラウド資源を作らない |
| データ | 基礎版は公開企業一覧・企業IR・持込資料を使う。有料契約・無料トライアル・クレジットカード登録を必要とする経路は使わない。EDINET公式APIは費用・登録条件の確認後に追加できる任意経路 |
| 株価 | 出典と基準日が分かる終値CSV・手入力を標準にする。全社の最新株価を自動無料取得できるとは想定しない |
| 抽出 | XBRL・CSVの規則抽出と原本確認。PDFの目視入力も正式な経路として扱う |
| AI・OCR | 外部LLM・クラウドOCRを呼ばない。ローカルモデルも必須にしない。読めないPDFを有料処理に自動転送しない |
| 画面 | ローカルで起動した既存Asset Hubで閲覧。本番Cloud Run・クラウド保存・公開デプロイは利用しない |
| 更新 | 当初は手動実行。Macを起動している時だけ動き、24時間監視は保証しない |

ここで0円とは、本システムのデータ取得・解析・計算・表示に追加の有料サービス契約や従量課金を必要としない意味である。既存Mac・回線・電力、人の調査時間は別であり、既存Asset Hubのクラウド費用を停止・削減する作業も含まない。開発を支援する既存サービスの契約とは分けて扱う。

提供元の利用条件や無料経路が変更された場合は、その経路を停止して手動取込へ切り替える。有料サービスへ自動的に移行しない。料金・利用条件・仕様の公式確認は[無料版の取得条件と出典](free-data-sources.md)に集約し、個別機能の取得期間や収録率を未確認のまま保証しない。現時点では、EDINETの現行公式資料がAPIの0円を明示しているとは確認できていないため、APIを無料構成の必須条件に置かない。課金への同意を求められる経路は停止する。

## 2 何を材料にし、何が残るか

| 必要情報 | 基本経路 | 無料版での扱いと限界 |
|---|---|---|
| 探索対象の企業一覧 | JPXの公開企業一覧を取り込み、取得日を付けて保存 | 対応する市場・商品区分を確認する。JPXの一覧だけで地方取引所を含む日本の全上場企業を網羅したとは表示しない |
| 財務・CF・株数・大株主 | 人が保存した有報・XBRL・会社資料を取り込む。EDINET公式APIは任意の追加経路 | APIにはキー登録が必要で、費用・登録条件確認後のみ有効化。公表、訂正、提出期間、連結・単体を識別。未対応タグや未収録項目は目視確認へ回す |
| 足元の決算・資本政策・役員 | 企業IRの資料、ユーザーが保存したPDF・HTML・CSV | サイトごとの条件を確認。初期は人がURL・資料を登録し、画面全体を無差別に巡回しない |
| 適時開示・MBO第一報 | 公開TDnetを人が確認し、会社IRの原本等を登録 | 公開TDnetの自動スクレイピングは採用しない。全社の即時通知・取り漏れゼロは保証しない |
| 株価・出来高 | ユーザーが利用条件を確認して取得したCSV、候補ごとの終値手入力 | 証券口座への自動ログインは不要。価格の時点・調整基準・出典を必須とし、未入力なら割安率を出さない |
| 借入条件・換金可能資産 | 有報注記、会社資料、原本からの確認入力 | 公開されていない融資条件や資産処分の可否を推測で埋めない |
| MBOの実際の意向 | 公式に開示された検討・提案・取引資料 | 非公開の意向は分からない。公に具体的な検討が報じられた後は未発見候補から外す |

EDINETの書類一覧は提出資料を見つける入口であり、上場普通株の母集団そのものではない。企業一覧とEDINETコードを対応させ、未対応企業を残す。社名だけで自動名寄せせず、証券コード・法人番号・根拠で確認する。APIを利用しない場合も、手動で保存した資料を同じ台帳に登録する。公開サイトで過去資料を閲覧できることを、機械による一括取得が認められていることと読み替えない。

CSVにはUTF-8の標準取込形式を用意する。公開企業一覧等が表計算形式の場合は、形式に対応した無償のローカル読取ライブラリ、または利用可能な表計算ソフトからのCSV保存を使う。有料のExcelを必須にしない。PDF本文の自動抽出は無償のローカル処理器を追加できるが、画像PDFは目視転記でも完結する。

## 3 価格を必要としない探索と、価格付き評価を分ける

### 3.1 母集団と処理状況を先に作る

企業一覧を取り込むと、各企業を次の状態で管理する。

`未処理 → 資料取得済み → 一次選別可能 → 詳細確認候補 → 価格評価可能`

これとは別に、除外・取得失敗・資料不足・案件監視を管理する。初期の自動価格評価対象は非金融の上場普通株とし、金融・保険、REIT等は対象外または専用方式待ちと明示する。種類株、重複上場、上場廃止も区分し、消去して履歴を失わない。

一覧全体を登録しても、全社を評価したことにはならない。画面の上部に「企業一覧登録数／資料取得数／一次選別可能数／価格評価可能数」と基準日を常時表示する。

### 3.2 初回20〜30社の決め方

初回は開発と調査の実現性を確かめる標本とし、将来のMBO的中率を測る標本とは呼ばない。たとえば24社なら、次を各8社とする案を置く。件数は設計上の仮定である。

- 財務データを処理できた企業から、CFや資金負担の条件が良い企業。
- 公開資料で経営陣・創業家・資産管理会社の持分関係を確認できる企業。
- 上記に偏らないよう、複数業種から固定した乱数種で選ぶ比較対象。

重複は別の企業に置き換え、選定理由を保存する。処理できた企業だけを選ぶ偏りは残るため、その母集団と未処理数を表示する。過去の有名MBOだけを並べない。INFORICHは着想源であり、配点の調整や成績評価には使用しない。

### 3.3 一次選別：株価なしで調査順を決める

各企業について、実績CFの継続性、設備投資・運転資金負担、借入と現金、収益の変動、開示された所有関係を確認する。単一のMBO総合点を作る代わりに、次の調査リストを並べる。

| リスト | 入る条件の初期案 | 表示上の注意 |
|---|---|---|
| CFを詳しく見る | 3期分を比較でき、営業CFが各期プラス。設備投資後の資金残りも確認 | 3期という期間は仮説。営業CF−設備投資は一次選別用の概算で、DCF用FCFFとは別 |
| 所有構造を詳しく見る | 大株主と役員等の関係について、確認可能な公開資料がある | 持分の多寡をMBO確率へ変換しない。関係不明は否定材料ではなく未確認 |
| 資産・負債を詳しく見る | 現預金、借入、投資有価証券等を同一基準で比較できる | 帳簿上の現金超過を、そのまま余剰現金や割安と呼ばない |
| 新規・未処理を確認する | 新しい提出書類、母集団への追加、未処理企業 | データが豊富な企業だけが繰り返し上位になることを防ぐ |

リスト内では資料の更新日・確認状況・業種を使い調査順を決め、並べ替え条件を画面に表示する。数値閾値や重みを追加する際は「設計仮説・未検証」として版を付ける。数値のない項目に平均値やゼロを入れて順位を作らない。

毎回の新規調査枠を設け、既存候補の更新だけで終わらせない。週5社を調べるなら、例として既存候補2社・新規抽出2社・比較対象1社を配分する。人の作業時間を測り、件数を変更してよい。これは作業量の目安であり、達成実績ではない。

### 3.4 二次評価：上位候補にだけ価格を付ける

詳細確認に進む企業に、終値、価格日、通貨、分割調整の有無、出典を入力する。価値計算の確認に必要なデータがそろった企業だけ、価値の幅と価格との差を表示する。

価格未入力の企業は「割安度未評価」。価格日が違う企業はそのまま同一基準日の順位へ混ぜず、同日比較と最終価格参考を切り替える。古い価格は「○日時点の比較」と表示する。価格の鮮度基準も設定値として明示し、現在価格のように見せない。

## 4 一覧に並べる四つの結果

| 結果 | 内容 |
|---|---|
| MBOの条件 | 所有構造、公開された動機、資金面、主要株主等の障害を、確認済み／未確認／反証ありで表示 |
| 単独継続の株主価値 | MBOが起きない場合の弱気・基準・強気の1株価値、価格との差、弱気ケースの損失幅 |
| LBOの成立価格 | 仮の借入・出資条件を満たせる株式取得価格の範囲。銀行の融資承諾やTOB価格の予測ではない |
| 根拠の強さ | 原本、確認箇所、公表日、取得日、未確認数、矛盾、最終確認日 |

MBO条件の状態や調査順を「12か月以内○%」に置き換えない。初期版はMBO確率を表示せず、当初案にあった確率校正・機械学習を完成条件から外す。肯定材料・否定材料・見方を変える条件を同時に表示する。

## 5 無料版でも省かない計算確認

### 単独継続価値

DCF用のCFは、一次選別の概算CFから別に作る。連結範囲と会計基準を確認し、利払い前の営業利益から、税、減価償却、設備投資、運転資本増加を調整したFCFFを求める。利払い後CFを同じ割引率で混ぜない。

```text
事業価値 = FCFFの現在価値 + 継続価値の現在価値
株主価値 = 事業価値
         + DCFに含めていない余剰現金
         + 重複しない非事業資産の税引後処分価値
         − 有利子負債等の帰属調整
1株価値 = 株主価値 ÷ 定義した希薄化後株数
```

現金・借入・資産の調整表を必須にし、次を検査する。

- ネット負債を控除した後に、同じ現金をもう一度加算しない。最低必要現金、用途制限現金、子会社から移せない資金を区別する。
- 土地・政策保有株を売却価値として足す場合は、関連収益を事業CFや継続価値へ重ねて入れない。税・処分費用・事業継続への影響を考える。
- リース支出をCFに残す方法と、リース債務を負債として引く方法の整合を取る。元利支払と負債控除の二重負担を避け、リース基準の異なる同業倍率を混ぜない。
- 非支配持分、年金、退職給付、希薄化等、重要な項目は原本確認か明示した仮定が必要。単位、円・外貨、連結・単体、累計・単独期を混ぜない。
- 株価、発行済株数、自己株式、希薄化後株数を同じ分割基準へ合わせる。未調整価格に現在の調整済株数を掛けない。

弱気・基準・強気の成長率、利益率、税率、割引率、長期成長率は独自シナリオと明記する。推計が必要な維持設備投資や必要運転資金は範囲を置き、推定のまま示す。重要項目を埋められない場合、または永久成長式で成長率が割引率以上の場合は計算保留。DCFを無理に出さず、調整純資産や実績倍率までの表示にとどめられる。

希薄化後株数と比較株価は正の有限値を必須にする。負債等を控除した残余が0以下の場合は「このシナリオでは株主残余価値なし」と表示し、負数をマイナスの株価として扱わない。基準1株価値が0以下なら割安率を計算せず、割安順の比較から外す。負の価値を分母にして100%を超える割安率を出す誤りを防ぐ。

### LBO成立価格

初期の保有期間は5年を仮置きし、借入額、金利、返済、業績、設備投資、出口倍率、要求収益率のシナリオを人が入力する。無料で市場の融資条件を取得できるとは想定せず、借入条件を実勢値と呼ばない。

株式取得対価・借換え・手数料等の資金使途と、出資・借入・利用可能現金等の調達を一致させる。買収時の現金と保有中CFを重ねて原資にしない。各年の利息・税・投資・返済後に最低現金を維持できること、出口の残債控除、スポンサーへの配分を確認し、成立する価格を逆算する。経営陣の持分継続は、必要現金と経済的な持分の双方に反映する。

データ不足は「計算保留」、仮定下で成立する価格がない場合は「この条件では成立範囲なし」。MBOの成立不能と断定しない。単独継続価値、LBO成立価格、少数株主への実際の買付価格は別物として表示する。

## 6 ローカル構成と処理の流れ

```text
公開企業一覧／人が保存した有報・IR・XBRL・価格CSV
  → 原本・出典・日時・ハッシュをローカル保存
  → CSV・XBRLの規則抽出／目視入力
  → 単位・時点・連結範囲・株式分割の確認
  → 価格なし一次選別
  → 選んだ企業へ価格・注記・独自仮定を追加
  → 価値・LBO計算と検算
  → 日付別スナップショット
  → ローカルAsset Hub

任意追加：条件確認後のEDINET公式API → 同じ原本保存・取込経路
```

Python標準ライブラリのSQLite・CSV・XML処理を中心とする。XBRLは年度ごとのタグ・コンテキスト・期間・単位を対応表で処理し、未対応タグを黙って近い科目に割り当てない。企業独自タグ、会計変更、訂正は確認待ちへ回す。PDF処理や表計算形式の読取に追加ライブラリを使う場合も無償のローカル処理に限定する。

今後の配置案は次のとおり。今回これらのプログラムやデータは作成していない。

```text
backend/mbo/                       # 取込・抽出・検算・選別・価値計算
data/private/mbo/state.sqlite      # 企業・原本・数値・根拠・確認状態
data/private/mbo/raw/              # 取得・持込原本。版を保存
data/private/mbo/imports/          # 価格・手動確認用CSV
data/private/mbo/runs/             # 実行記録と日付別出力
```

最小テーブルは企業・証券ID、母集団版、原本版、数値と根拠、所有関係、価格、イベント、確認履歴、計算前提、実行記録とする。[無料版の保存モデルとAPI](free-technical-design.md)を使い、LLM関連列や有料費用管理は必須にしない。

ファイルやローカルCLIから書き込み、画面は読み取り専用にする。Asset Hubの既存サーバーに専用モード `--mode mbo-local` と専用画面 `web/mbo.html` を追加する案とし、既存の資産・コスト・GCP処理を初期化せず起動する。これらは今後実装する仕様であり、現行コマンドではない。既存画面部品を再利用し、ローカル起動時だけ有効な読取経路で確認済みJSONを配信する。待受はループバックに限定し、APIキーやSQLite本体をブラウザへ渡さない。既存本番へ私有データを混ぜないよう、原本・価格CSV・実行結果をGit対象外に置き、公開研究フォルダへ自動出力しない。新しいHTTP書込API、クラウドDB、キュー、外部CDNは不要。

EDINETアダプターは初期無効とし、利用者が費用・登録条件を確認してキーを用意した場合にだけ有効化する。キーはローカル環境で収集処理だけが参照し、リポジトリ・引数・ログ・出力URLへ保存しない。キーがなくても起動・持込・選別・計算・表示を止めない。認証・サイトログインの補助が必要になった場合は共通site-login skillに従う。今回の設計保存ではキー作成・認証を行わない。

入力は実行命令として扱わない。HTMLのscriptやPDF内のリンクを自動実行しない。ZIP展開先、件数、サイズを制限する。外部取得は公式APIと確認した資料URLに限定し、タイムアウト・再試行上限・処理件数を設定する。

## 7 時点・再現性・失敗時の扱い

各原本と数値に、対象期末、公表日時、初取得日時、確認完了日時、訂正関係を保存する。財務期末を公表日と誤認しない。実運用の判断に使えるのは、公表・取得・必要な確認がすべて終わった時点以降である。今日初めて取得した資料の取得日時を過去へ戻さない。

入力ハッシュ、抽出ルール版、計算コード版、仮定、評価日時を実行記録に保存する。同一入力を再取込しても重複しない。訂正、手動修正、タグ対応の変更は旧値を上書きせず、新版と理由を残す。

更新失敗時は前回の成功版を表示し、その基準日・未取得件数・確認待ちを示す。途中の結果を最新完成版へ切り替えない。Macが止まっていた期間も表示し、「当該期間に重要開示なし」と読み替えない。原本を再取得できなくても前回保存版から計算を再現できるようにする。

## 8 画面は三つに絞る

1. **候補を探す**：母集団と処理率、業種、取得状況、価格なし一次選別、未調査候補、価格日が一致する企業の割安比較。表示中の対象集合を明示する。
2. **企業を確認する**：MBO条件、所有関係と未確認箇所、根拠・反証、原本リンク、実績と独自仮定、価値の三シナリオ、LBO感応度、次に読む資料。
3. **更新と記録**：持込CSV・資料の結果、失敗・未対応タグ、確認待ち、過去の候補、ルール版、第一報・正式公表・成立・撤回。具体的な検討報道後の企業はここで案件監視する。

定期実行・通知は初期要件に含めない。必要になった場合もローカル実行で設計し、実装時にユーザーの希望を確認する。

## 9 段階実装と完成物

期間は1名相当の実装と必要な人の確認を想定した仮置き。資料形式・不足項目・対応会計基準により変わる。無料版では、有料データを使った当初案の全社処理量や履歴検証期間を引き継がない。

| 段階 | 目安 | 完成物 |
|---|---|---|
| A：手動でも完結する入口 | 第1週 | 企業一覧取込、評価票・標準CSV、20〜30社の選定、必要項目と欠測の把握。価格・資料を持ち込める |
| B：持込資料の省力化 | 第2〜3週 | 原本保存、持込XBRL・CSVの対応済み項目抽出、訂正・単位・期間の検算、価格なし一次選別。EDINET取得は条件確認後の追加作業 |
| C：操作できる無料MVP | 第4〜6週まで | 確認済み企業の単独継続価値・LBOシナリオ、ローカルAsset Hub、日付別記録、未処理企業からの新規候補追加 |
| D：範囲の拡大 | MVP後に判断 | 対応業種・企業数・タグを拡張。件数は取得成功率、確認時間、Macの容量を測って決める |

最初の完成条件は「全市場を無人監視できる」ではなく、「未調査企業を含む登録母集団から次に読む会社を選び、その価格と原本を確認して評価を保存できる」とする。

## 10 受入条件

| 確認対象 | 合格条件 |
|---|---|
| 追加サービス費 | 取得・抽出・計算・表示の実行経路に有料サービス・外部LLM・クラウドOCR・クラウド計算の必須呼出しがない。接続できないときに有料経路へ切り替わらない |
| API不要の完結性 | EDINETキー未設定・APIアダプター無効・外部接続なしで、サンプル資料の持込、未登録企業の追加、一次選別、価値計算、LBO計算、ローカル閲覧まで完了する |
| 候補の新規発見 | ウォッチリストに未登録の企業も取り込め、価格なしで一次選別対象になる。登録・処理・評価可能の企業数が画面と一致する |
| 根拠 | 確定表示する主要数値・所有関係・主張は、原本と確認位置へたどれる。欠測・推測・矛盾を確認済みへ変換しない |
| 数値計算 | 単位、累計・単独期、連結・単体、自己株式、分割、税、現金と借入、資産二重計上を検算できる。重要項目欠測時は価格を出さない。株数の0・負数・非有限値を拒否し、基準価値0以下では割安率を出さない |
| LBO | 資金使途と調達が一致し、返済・最低現金・残債・出資者配分を追える。借入等の独自仮定が画面に見える |
| 時点 | 未来の開示や後日の訂正値を意図的に混ぜた試験で、過去の実運用記録から除外される。価格日と分割基準の不一致を検出する |
| 再現と復旧 | 同じ原本・ルール・仮定から同じ数値を再現し、再実行で重複しない。取得失敗でも前回成功版を閲覧できる |
| ローカル利用 | APIキーと私有データをブラウザ・ログ・Git・本番へ漏らさず、既存Mac上で閲覧できる |

必要なテストは上記の誤計算・将来情報混入・更新失敗を再現するものを中心にする。画面の文言をなぞるだけのテストを増やさない。API取得に依存しない保存済みサンプルで計算器を確認できるようにする。

## 11 無料版の限界と拡張を止める条件

無料版では、全銘柄のリアルタイム／当日株価、全開示の即時監視、公開資料にない実質所有者、融資確約、MBOの非公開意向を保証しない。過去の母集団・訂正前資料・第一報がそろうとは限らず、厳密な過去成績やMBO確率の校正はMVPの対象外とする。

最初は資料確認時間、数値修正率、未処理率、根拠到達率を測る。12／24か月以内のMBO初回正式公表を将来確認できるように、候補と理由を日時付きで保存する。期間未満の未発生を失敗確定とせず、撤回・競合買収・上場廃止を別に記録する。新規候補の発見と投資リターンを混同しない。

過去原本から再構成した例は「事後再構成」とし、当時稼働していたシステムの実績とは分ける。現在取得しやすい企業への偏り、業種・規模の偏り、株価を入力した企業だけの偏りを結果に併記する。

原本確認の時間が増えたら対象数や更新頻度を下げ、未対応業種を保留する。入力がそろわなければ価格計算を止める。無料経路が利用できなくなれば、保存済み資料と手動入力で継続するか、その経路を休止する。有料契約や自動課金を解決策として勝手に導入しない。

完全に外部通信をしない構成も可能だが、その場合は企業一覧・資料・株価を利用者が持ち込み、API収集を無効にする。候補の計算と整理はできる一方、新しい資料の発見は人が担当する。

## 12 実装前に残る確認

- EDINETの登録・利用条件、対象書類、取得・訂正仕様、レート制約と、初回企業での必要タグの充足率。
- JPX一覧の対象市場・商品区分・ファイル形式、EDINETへのコード対応、対象外市場を追加する場合の公開経路。
- ユーザーが持ち込める価格CSVの列・分割基準・利用範囲。用意できなければ終値の手入力から始める。
- 初回企業の原本確認時間、XBRLの未対応率、保存容量。無人の全社処理ができるという前提を置かない。

上記を確認するまでは取得範囲や自動処理率を断定しない。今回行うのは再設計の保存までであり、APIキー作成、外部への資料送信、システム実装、定期実行、デプロイは行わない。
