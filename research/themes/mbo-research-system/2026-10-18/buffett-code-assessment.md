# バフェットコードのデータをMBO調査へ使う場合の適合性

確認日：2026-10-18（日本時間）。対象は[データソリューション](https://business.buffett-code.com/data_solution)と、同ページが案内する公開OpenAPI v4の参照先定義。仕様ファイルに記載された版は2026-07-27。認証API・契約データの取得、見積依頼、契約は行っていない。

**現在のMBO候補を探して割安度を調べる用途では、バフェット・コードを主要なデータ源にできる見込みがある。財務・大株主・会社資料は広く提供されており、J-QuantsとTDnetを重ねて契約することを最初から前提にする必要はない。** 一方、売買用の株価履歴、当時の値による過去検証、実質所有関係、買収資金の詳細には、未確認または補完が必要な項目がある。

以下で「公開仕様では未確認」とした項目は、商品全体で提供されないと判断したものではない。データソリューションはAPI・MCP・データフィードを個別設計するため、公開APIに見えない情報を別形式で提供できる可能性がある。提供範囲と価格は必要項目を指定して確認する。[提供形態と個別設計の案内](https://business.buffett-code.com/data_solution)

## 1 今回の調査に使えることを確認できた情報

| 必要情報 | 公開仕様で確認できた内容 | MBOシステムでの使い道 |
|---|---|---|
| 財務 | 現預金、有利子負債、短長借入、リース債務、支払利息、営業CF、設備投資支出、FCF、純資産、投資有価証券、一過性損益等 | 割安度、利益の平準化、余剰資金、借入返済能力の一次評価 |
| 株価に対する評価指標 | 日次の時価総額、EV、PER、PBR、予想EPS、配当利回り等 | 候補の比較と順位付け |
| 大株主 | 大株主名、比率、分割前株数、現在基準へ調整した株数、評価額、匿名化フラグ | 経営陣持分や支配株主の調査の入口 |
| 経営陣と企業関係 | 役員の氏名・役職、関係会社の所有・被所有比率や関係説明 | 公開情報から支配・経営構造を整理 |
| 設備 | 土地、建物、機械、リース資産・使用権資産等の簿価と所在地等 | 余剰資産や資産価値の調査の入口 |
| 開示資料 | 有報、決算短信、適時開示、大量保有・変更報告、中期計画等の資料検索とダウンロード | 資本政策、会社の課題、買収に関する根拠・反証の調査 |
| 公表・変更の情報 | 資料の公表時刻、財務の初回開示日時・最新開示日、業績予想修正一覧 | 情報の時点をそろえ、変更資料を追う |

これらは公開APIの定義に項目があることの確認であり、全社で非欠測であることや、希望する契約へ全部含まれることの確認ではない。設備と関係会社のAPIは公開説明でベータ版とされている。

財務項目は[四半期財務スキーマ](https://docs.buffett-code.com/assets/components/schemas/v4/jp/companies/quarterly/show/attributes.yml)、評価指標は[日次スキーマ](https://docs.buffett-code.com/assets/components/schemas/v4/jp/companies/daily/show/attributes.yml)、大株主は[大株主スキーマ](https://docs.buffett-code.com/assets/components/schemas/v4/jp/companies/quarterly/major_shareholders/index/attributes.yml)、資料は[資料検索スキーマ](https://docs.buffett-code.com/assets/components/schemas/v4/jp/documents/search/attribute.yml)で確認した。

## 2 補完が必要になりそうな情報

### 売買に使う株価と出来高

日本企業向けの日次APIの公開スキーマは時価総額・評価指標が中心で、株価の始値・高値・安値・終値、出来高、株式分割係数、実際の配当支払日の項目は確認できなかった。これらがデータフィード等で提供可能かを確認する。

候補の比較には日次評価指標を使えるが、「翌営業日に買えたか」「売買費用や配当を含めて利益が出たか」の検証には、株価・出来高と企業行動の履歴を補う。価格をPERや時価総額から逆算して、検証用の実際の取引価格とみなさない。[公開日次項目](https://docs.buffett-code.com/assets/components/schemas/v4/jp/companies/daily/show/attributes.yml)

### 当時公知だった財務の全項目と過去の銘柄母集団

四半期APIは、訂正や有報などに応じて更新され、通常は最新の値を返す。初回開示日時や当初会社予想が取得できても、全科目の訂正前の値を任意の過去日時で取り出せる保証にはならない。例えば、後日の有報で初めて開示された数値を、先行する決算短信の公表日にすでに分かっていたものとして使うと未来情報が混ざる。[財務APIの更新方針](https://docs.buffett-code.com/assets/paths/v4/jp/companies/quarterly/show.yml)

企業属性には上場廃止の区分があり、資料にも過去の廃止企業が含まれることを示す説明があるため、「上場廃止企業を扱っていない」とは言えない。ただし、当時の全上場企業一覧、上場廃止日、コード変更履歴、各履歴の網羅性は公開仕様だけでは確認できない。[企業属性](https://docs.buffett-code.com/assets/components/schemas/v4/jp/companies/show/attributes.yml)

バックテスト用には、原資料による当時値の再構成、取得後の版管理、過去の上場企業一覧との照合を用意する。17期以上の資料・財務の蓄積と、当時知り得た情報を再現できることは分けて確認する。

### 創業家や資産管理会社を含めた実質持分

大株主APIはあるが、匿名化により氏名がnullになる場合があり、公開説明では通常第1・第3四半期に大株主情報の開示はない。株主の基準日と公表日を確認する。現在基準に調整された株数を、そのまま過去の株価に掛けない。[大株主APIの説明](https://docs.buffett-code.com/assets/paths/v4/jp/companies/quarterly/major_shareholders/index.yml)

役員APIの公開スキーマは氏名と役職を中心としており、役員個人の持株数、親族関係、創業者区分、資産管理会社の最終的な支配者、役員一覧の過去版まで構造化して取得できるかは未確認。経営陣が実質的に何%をまとめられるかは、有報・大量保有報告・会社資料を照合する工程を残す。名称が似ていることだけで同一関係者と確定しない。[役員項目](https://docs.buffett-code.com/assets/components/schemas/v4/jp/companies/officers/index/attributes.yml)

### 資産の売却価値と借入契約の細目

設備の簿価と財務の借入総額は確認できるが、不動産の時価、担保・処分制限、用途制限のある現金、借入ごとの返済期限・金利・財務制限条項、維持投資と成長投資の区分が一括した構造化データとして得られるかは未確認。

これらは原資料に記載される範囲を補足し、未開示部分は仮定の幅を置く。簿価から含み益を決めたり、現預金の全額をMBOの買収資金に利用できるとみなしたりしない。[設備項目](https://docs.buffett-code.com/assets/components/schemas/v4/jp/companies/quarterly/major_facilities/index/attributes.yml)

### MBO案件の分類と最初の検討報道

資料検索にはTOBタグと公表時刻がある。一方、MBOと親子上場解消の区別、成立・撤回・価格変更・競合買付、最初の具体的な検討報道まで整理した案件台帳は、今回確認した公開v4の定義では見当たらなかった。M&A検索等の別機能・個別データ納品で提供できるかを確認し、足りない部分は公式資料と報道の原文から作る。[資料タグ](https://docs.buffett-code.com/assets/components/schemas/v4/jp/documents/search/attribute.yml)

非公開のMBO意向、秘密の交渉、家族内の承継意思、銀行の実際の融資提示条件は、公開情報を集める設計では確認できない。この部分はデータ契約を増やして埋める前提にせず、候補の仮説と資金条件の感応度として扱う。

## 3 採用する場合の構成案

現在の候補調査では、バフェット・コードの財務・評価指標・大株主・会社資料を優先し、不足する実質所有関係と資産・借入注記を原本で確認する。TDnet資料の検索・取得が希望する契約で十分なら、TDnetの二重契約を急ぐ必要はない。

売買シミュレーション用の株価・出来高等が提供されない場合だけ、別の価格データを補う。J-Quantsを補完候補とする場合も、株主データ等が重複するか、必要な履歴年数は何年かを見てプランを選ぶ。過去検証のためにJ-Quantsを追加しても、財務の全項目の過去版や実質所有関係が自動的に解決するとは考えない。

日次の即時性については、データソリューションのFAQは新情報の反映を原則翌日としている。週次候補調査なら許容できる設計だが、当日の開示直後の監視を求める場合は、データ種別ごとの反映時刻を確認する。[更新頻度の案内](https://business.buffett-code.com/data_solution)

## 4 契約前に確認する事項

以下は契約前に確認する項目の整理。2026-10-18に[公式お問い合わせフォーム](https://www.buffett-code.com/contacts)から、サービス紹介・料金・契約条件の資料請求と、ライトプランとの差、CSVの外部分析ツールでの利用範囲、API契約の照会を送信した。送信完了画面と同日11:47頃（日本時間）のGoogle Forms回答控えを確認済み。控えに添付はなく、送信直後の確認時点では先方の資料・個別回答は未受領。フォームに示された返信の目安は通常1営業日。

1. **個人の本人用研究で契約できるかと最低料金**。日本上場株の財務、大株主、会社資料に絞った範囲と、API・CSV/TSV納品それぞれの見積条件。
2. **株価・出来高**。日本株のOHLC、分割調整、実際の配当履歴、廃止銘柄を含む履歴は提供できるか。
3. **財務の当時版**。訂正前の全科目、公表日時、訂正関係、数値ごとの出典資料IDを提供できるか。
4. **過去の母集団**。過去日指定での上場企業一覧、廃止日、社名・コード変更と合併の履歴はそろうか。
5. **株主と経営陣**。匿名化の対象・割合、実質所有関係、役員持分・履歴、大量保有の構造化範囲はどこまでか。
6. **買収・資産・借入情報**。MBO案件台帳、資産時価、借入契約明細の提供可否。原資料内にある場合と構造化済みの場合を分ける。
7. **取得運用**。対象企業の網羅性、欠測、種別別の収録開始、更新時刻、差分取得、回数・件数上限。公開仕様の閲覧だけでは実測できない。
8. **保存とAI利用**。本人用の非公開クラウド、外部LLMでの処理、派生指標・原本・予測履歴の保存、契約終了後の保持について、適用契約で許される範囲。

このうち現在のMVPの採用可否は1・5・7・8、過去検証の採用可否は2・3・4を優先して判断する。未回答の項目があっても、取得できたデータの範囲で候補調査を試すことと、予測精度を検証済みと判断することを分ける。

## 5 ライトプランで始める場合

同日に[公式料金ページ](https://www.buffett-code.com/pricing)をブラウザで確認し、ライトの表示価格が月990円であることを確認した。データソリューションのAPIとは別の、画面閲覧・CSV取得を中心とするプランである。

| 項目 | ライトの公式表示 | 初期の使い方 |
|---|---|---|
| 条件検索 | 国内上場企業、検索120項目、200企業まで表示、CSV月20回 | 条件を保存し、月1回候補CSVを取得 |
| 企業比較 | 200項目比較、CSV月20回 | 候補企業を横並びで確認 |
| 業績・指標 | プラン概要は7期、詳細表はサマリー以外7年 | 長期の傾向を画面で確認 |
| 業績CSV | 5年、月20件。四半期CSVは対象外 | 上位5〜10社の年次データを取得し、基礎評価 |
| 株価CSV | 月20件。CSV自体の取得年限は料金表では未確認 | 候補の価格を取得し、列・分割調整・年限は実ファイルで確認 |
| 株主・資料・M&A | 現在株主の全件閲覧、実質株主氏名表示、資料全文検索、M&A検索は対象外 | 有報・大量保有・会社IR等の原本で補完 |
| API・拡張連携 | Web APIは別途問い合わせ。Excel/Sheetsアドオンはライト対象外 | CSVの取込後の計算を自動化し、サイト側の取得は手動 |

CSVの各種上限を合算した回数を利用可能枠として扱わない。料金ページには1CSVあたりのデータ量制限や回数に関する注記もあるため、試作時に用途別の消費と出力範囲を確認する。表示できる項目のすべてが希望どおりCSVへ出力されるとは仮定せず、最初の実ファイルで現金、負債、営業CF、設備投資、単位と対象期を確認する。

**設計上の判断は、月次の手動CSVを使った候補探索と5〜10社の深掘りなら、ライトを初期案にできるというもの。** 全社の日次自動更新、資料の自動取得、全社の四半期財務、当時値による厳密な履歴検証は、この構成だけで満たすとは判断しない。

具体的には、月1回の条件検索CSVから20社程度を選び、上位5〜10社の業績CSVを取得し、株主構造と資本政策を原本で確認する。数値の正規化、割安評価、調査票生成をシステム側で行う。四半期の詳細が必要な場合は原本で補い、未校正のMBO確率は表示しない。取得範囲・保存・AI処理の適用条件は確認した上で使う。

データ契約に先立って、無料枠で取得できるサンプルCSVの列を確認し、その後ライトの取得枠が必要かを判断する。これにより、初期段階から法人向けAPI一式を契約する工程を外せる。
