# 無料構成で使う公式データと取得条件

確認日：2026-10-18（日本時間）。対象は金融庁公式EDINETとJPXの公開情報。公開ページ・仕様書の調査のみで、ログイン、APIキー発行、認証APIの試行、契約、外部問い合わせは実施していない。[無料版のシステム設計](report.md)の無料構成を検討するための資料。

**公開資料の手動取得とローカルでの集計を起点にすれば、有料データ契約なしで試作できる。全市場の最新株価・開示・過去時点データを、無料かつ自動で一括取得できることまでは確認できていない。** 閲覧できること、機械取得できること、取得物を別用途へ使えることは、それぞれ確認する。

## 1 経路別の確認結果

## 2 EDINETの料金と公式・第三者の区別

現行の[EDINET利用規約](https://disclosure2dl.edinet-fsa.go.jp/guide/static/disclosure/WZEK0030.html)、[2026年6月のAPI v2仕様書](https://disclosure2dl.edinet-fsa.go.jp/guide/static/disclosure/download/ESE140206.pdf)、[公式FAQ](https://disclosure2dl.edinet-fsa.go.jp/guide/static/disclosure/WZEK0090_001.html)を確認した。APIキー発行・利用手順は記載されているが、**APIの料金が0円であるという現行の明示文言は、この範囲では見つからなかった**。有料だと判明したわけでもない。料金記載を見つけられないことだけで、無償を証明したとは扱わない。

旧「EDINET API機能利用規約」`ESE140191.pdf`については、検索結果に無償の記述が残る一方、元URLの本文を今回取得できなかった。検索キャッシュを現行の料金根拠には採用しない。

金融庁公式のAPIホストは `api.edinet-fsa.go.jp`、仕様・ガイドは `disclosure2dl.edinet-fsa.go.jp` である。「EDINET DB」等の第三者サービスの料金、無料枠、APIキー、正規化データは、金融庁公式APIの条件を示すものではない。本資料では第三者の無料枠を公式APIの無償根拠に使っていない。

現行EDINET規約は公共データ利用規約PDL1.0への準拠、出典・加工主体の表示等を案内している。これはAPI料金の明示とは別の事項である。個々の資料や第三者権利、外部LLM処理・再配布の細かな適法性まで一律に判断するものではない。[F01、F11]

## 3 EDINETの取得範囲と実装上の条件

- **認証**：API v2の書類一覧・書類取得にはキーが必要。通常の公開資料閲覧と、API用のアカウント・キー準備は別工程にする。今回はいずれの認証も行っていない。[F02 §2-3、§3-1-1、§3-2-1／F03 API Q1・Q17]
- **取得形式**：一覧はJSON、本文書・監査報告書等はZIP、PDFはPDF、XBRLから変換されたCSVはZIPで提供する。CSV・XBRLが存在するかは書類別のフラグで判定する。CSVは全企業の分析用指標をまとめた完成データベースではない。[F02 §3-1-2、§3-2]
- **期間**：一覧の日付指定は直近の財務局営業日を基準に10年を経過していない範囲。本文の取得は書類ごとの縦覧・延長期間に依存する。有報・半期・四半期の閲覧期間10年には対象書類・提出時期等の条件があり、すべての書類が10年取得できるとはしない。[F02 §1-2-2、§3-1-1]
- **時点**：提出日時・書類管理番号・訂正関係・取下げ等を記録する。後から取得した過去の日付の一覧が、当時の応答を完全に再現するとは限らない。API運用開始前についても、修正前の情報等を含まない場合があると仕様に記載されている。[F02 §3-1-3〜§3-1-9]
- **アクセス**：機械取得には公式APIを使う。規約にはAPIで取得できないコンテンツに関する例外があるが、本設計はその例外を一般的なスクレイピング許可として使わない。FAQの「1分に1回程度」は書類一覧の更新間隔の説明で、全API共通の呼出上限と読み替えない。[F01 II・III／F03 API Q6]

実装案は、日次の一覧取得、必要な候補資料だけの取得、キャッシュ、再試行間隔、429応答時の待機を組み合わせる。大量の過去資料を一度に取得することは初期要件にしない。株価の継続的な配信機能は、ここで確認したEDINETの書類APIの提供範囲に含めない。

## 4 JPX公開情報の使い分けと残る穴

**31日は適時開示情報閲覧サービスの掲載期間であり、JPX全体の資料保存期間ではない。** 東証上場会社情報サービスには過去10年の適時開示という別経路がある。JPXのFAQには5年という記載も残るため、本設計ではサービス説明ページとTDnet概要の10年という案内を採用し、個別資料の存在を確認する。10年分の一括自動取得権限を確認したという意味ではない。[F04–F06、F10]

東証上場銘柄一覧は月末値を毎月差し替えるため、現在のファイルだけでは過去の在籍一覧を再現できない。廃止一覧には理由等があるが、これだけで未成立・撤回を含む全MBOの初回公表台帳は作れない。正式公表・結果・廃止を別イベントとして原資料から登録する。[F07–F08]

過去株価資料は特定銘柄・特定日の個別確認を想定し、手動取得を基本とする旨が記載されている。最新価格の網羅性、分割調整、出来高、配当、約定可能性をそろえた無料一括経路は未確認である。価格には必ず基準日と出所を付け、取得できない銘柄を価格欠測として残す。[F09–F10]

無料の初期版は次の順序が現実的である。

1. 月末銘柄一覧を手動保存し、公開資料から財務と所有関係で一次候補を作る。
2. 候補5〜10社の最新開示・株価を人が確認し、資料をローカルの抽出・計算処理へ渡す。
3. 価格を確認できた候補だけ割安率を計算する。価格がない会社は財務・MBO条件だけを表示する。
4. APIの追加費用が発生しないことと利用条件を確認できた後、EDINET部分を自動化する。JPX無料閲覧を自動巡回する設計にはしない。
5. 当時の母集団・原資料・価格が十分そろわない間は、全市場の的中率・売買成績・MBO確率を検証済みとして表示しない。

これはデータ契約費をかけない運用案であり、開発・人手確認・通信・保存・外部LLM等の費用までゼロだとするものではない。外部LLM APIやクラウドを使わず、手元の保存済み資料と定型計算から開始できる。
